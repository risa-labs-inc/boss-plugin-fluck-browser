# Native release review follow-up

The terminal-history change is paired with [BossConsole #650](https://github.com/risa-labs-inc/BossConsole/pull/650).
This records the disposition of the [latest automatic review](https://github.com/risa-labs-inc/boss-plugin-fluck-browser/pull/45#issuecomment-5670000303), including its [continuation](https://github.com/risa-labs-inc/boss-plugin-fluck-browser/pull/45#issuecomment-5670006224).
It also addresses the [subsequent final-head review](https://github.com/risa-labs-inc/boss-plugin-fluck-browser/pull/45#issuecomment-5670166211).

- **Final displacement and preview calibration:** hardware validation remains required. Taking the maximum of displayed and native travel is not safe: queued input can reduce net horizontal displacement when the user eases back. Keeping the maximum would navigate after that cancellation. The existing regression deliberately checks a completed preview followed by a native end below threshold. Neither the calibration factor nor this cancellation policy was changed without hardware evidence.
- **Unavailable observation:** keep the required fail-closed behavior; an inactivity fallback would reintroduce navigation while fingers are held down. The surface now logs once when enabled navigation is suppressed by `unavailable`, pointing to the host's trackpad settings. The paired host distinguishes permission denial from observation failure and supports retry.
- **Stationary holds and liveness:** terminal-history support is also a host lifecycle guarantee: disable, tap interruption and run-loop failure cancel claimants; failure publishes `unavailable` and releases native resources. The paired host tests these cases, including exceptions and unexpected run-loop return. An arbitrary inactivity ceiling would reject a valid stationary hold despite that guarantee. Older phase hosts retain the ten-second cancellation watchdog. Neither path idle-commits.
- **Cold-start capability:** the paired host eagerly publishes an empty terminal-history property in `MacOSScrollGesturePhases.kt:218-221`, in the same initializer that publishes `unavailable`; it does not wait for the first release. Therefore the first stationary hold is recognized as reliable. A plugin regression pins that an empty history value, unlike a missing property on an older host, permits an indefinite stationary hold.
- **Property and identity invariants:** the paired host never clears an initialized phase/history property. It writes `unavailable` on disable/failure. Contact IDs remain monotonic across observer restarts for the host process lifetime. These invariants are now in the wire-contract KDoc.
- **Missing AWT timestamps:** preserve the existing fail-closed behavior and diagnostic. Falling back to quiet-time navigation would violate the native-release requirement; no new evidence supports changing the supported AWT timestamp contract.
- **Pointer-handler ordering:** `prepareHomeSwipeScroll` now owns reconciliation, release decision, contact reset and the event gate. The composable calls that function. Tests execute the production function for overwritten release recovery, duplicate release, an unqualified prior release followed by a new contact, cancellation, malformed history, timestamp rejection and disabled navigation.
- **Lazy history and read ordering:** reconciliation now accepts a history supplier and invokes it only when the already-read raw phase belongs to another contact. This structurally keeps the raw snapshot before retained history and avoids history reads for the common matching-contact, missing-gesture and unavailable paths. Both the phase source and production pointer preparation use that API; a regression records read order and early-path laziness.
- **Per-event setting snapshot:** each pointer event reads `homeSwipeEnabled()` once and uses that answer for release decisions, diagnostics and affordance updates, including a legacy gesture completed by that event. Timer and watchdog completions still take a fresh setting snapshot when they run.
- **Reset cancellation:** the reset branch no longer calls `guard.cancel(current)`. A reset there can only see an empty gesture or follow the earlier mismatch path that already latched and cleared the old contact, so the call could never add a rejected ID.
- **Timestamp exception for retained releases:** retained terminal evidence is decided before gating the newly arrived event, so a qualified old release navigates even when that new event has no AWT timestamp. The production preparation regression now asserts this explicitly. Missing timestamps remain fail-closed for accumulating the new contact.
- **Timestamp tolerance window:** the 120 ms skew allowance can admit trailing samples when contacts are less than that far apart. The window is time-bounded, and event-count and travel checks mitigate accidental acceptance, but enough queued input could still satisfy both; physical rapid-contact validation remains required. Adding host end timestamps would widen the wire protocol without evidence that this bounded tradeoff is harmful.
- **Watchdog extraction:** the owned-action helper already pins stale-effect ownership, legacy timeout and reliable lifecycle decisions. Extracting the small coroutine reaction loop would add indirection without covering Compose effect scheduling, so it remains unchanged.
- **Compose polish:** density is now read once for both puck conversions, and the native-final sign convention is documented. Primitive Compose state specialization was left alone because it is unrelated to release correctness and would provide no meaningful behavioral coverage.
- **Shared cancellation:** Exit intentionally prevents the same physical contact from restarting on a sibling home surface. The surface comment now states this. Monotonic IDs prevent a disposed tab's rejected contact from poisoning a later contact.
- **Versioning:** the shared `BossConsole-Releases/.github/workflows/plugin-release.yml` workflow defaults `version_increment` to `patch` and commits the version bump before building. Keeping `1.2.29` in this PR does not re-release that version; no manual bump or manifest edit is needed.
- **Other small observations:** diagnostic flags and the event timestamp now live in a remembered plain holder rather than unobserved Compose state; the logger is hoisted. `pageRejected` remains an explicitly ignored compatibility field because the home detector uses its own tuned threshold. Parsing the small phase record twice is not a correctness issue.

The physical check remains outstanding on the paired build: hold/release, reversal and easing, short flick, nested scrolling, home preview/release consistency and rapid contacts under UI load. Automated tests are not reported as physical-trackpad validation.
